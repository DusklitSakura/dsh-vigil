# 已知限制与安全边界

> DSH VIGIL 的目标是降低风险、让不确定性可见，并在部分场景下保留恢复路径。它不是安全边界、沙箱或完整的终端监控系统。

## 1. 权限与信任边界

1. **不是安全边界。** 插件以 Harness 宿主进程权限运行；同权限攻击者可直接替换插件或删除 / 修改其状态，届时防护可能失效。完整性检查只能让一部分替换可见，不能阻止替换。
2. **DSH VIGIL 自身有权限。** 它读取插件目录、注册工具钩子，并写入审计日志与隔离区。启用 Sage 或显式配置外部模块路径时，还会加载外部代码。建议在部署前先审计本插件自身。
3. **自保护只覆盖部分入口。** guard 主要保护模型工具调用，不保证覆盖用户通过 UI 直接调用插件管理 Remote 服务的所有操作。紧急停机开关会绕过 guard，以免无法恢复。
4. **Sage 是第三方代码。** 启用 Sage 会下载固定版本的 `@gendigital/sage-core` 与规则资源；引擎会在 Harness 宿主进程内 import，因此相当于在宿主权限下执行第三方代码。安装流程禁用 lifecycle scripts 与可选原生依赖，但这不等于引擎本身经过安全审计。
5. **自动升级代表信任 registry。** Sage 自动升级会检查 npm `latest` 稳定版，执行版本与加载校验，失败回滚；它不会替用户完成 API 兼容性审查。要求完全可复现时，应关闭 `autoUpdate` 并固定可信版本 / 路径。

## 2. 静态审计边界

6. **静态扫描无法覆盖运行时可变行为。** 插件从网络下载脚本后再执行时，扫描器最多标出动态执行能力，无法预知未来下载内容。
7. **编码与混淆不是完全可逆。** base64 / hex 字面量会尝试解码后匹配；变量之间传递、动态拼接、加密或运行时构造的载荷无法可靠还原。
8. **扫描不会执行目标代码。** 这是有意的安全边界：扫描只做文本、规则与可选 AST 分析，不会完整模拟插件运行时行为或通用数据流。
9. **入口和非文本文件可能无法完全覆盖。** 大文件、深度超限、二进制、跳过目录或不可读文件可能没有进入扫描。报告会计入跳过 / 截断等状态，但扫描结果仍不等于证明没有风险。
10. **AST 只是一种增强。** Acorn 对部分 JavaScript 文件进行别名分析；TS、JSX、语法错误或不支持的语法会回退正则。没有 Acorn 时仍能扫描，但 AST finding 不会产生。
11. **扫描自身可能误报。** 扫描 `dsh-vigil` 源码时，规则表、说明文字与文档示例中的模式字面量也可能成为证据。不能通过 manifest 自声明字段豁免；`fixtures/**` 中故意保留的恶意样式文本仍会如实报告。
12. **测试夹具包含惰性恶意样式文本。** `fixtures/audit/**` 用于验证 `curl ... | sh`、密钥形态、外发 URL 等规则；这些样本不会被导入或执行，但杀毒软件可能误报 / 隔离。恢复办法见 [`fixtures/README.md`](../fixtures/README.md)。安装包的 `files` 白名单不包含 `fixtures/` 与 `test/`。
13. **能力命中不是恶意结论。** 例如出现外发 API、shell 调用或读取凭证路径，可能是插件功能的一部分。报告说明“检测到什么”，是否可信仍需结合来源、调用上下文与源码判断。

## 3. 运行时与删除策略边界

14. **删除覆盖不完整。** 脚本内部拆分删除、编码混淆、AMSI 绕过，以及未覆盖工具中的文件系统操作可能漏检。
15. **语言运行时中的删除不在完整覆盖范围。** 例如 `node -e`、`python -c` 或 `bash script.sh` 内部自行执行的删除，不保证能被外层命令解析器还原。
16. **规模估算不是精确统计。** 文件数 / 字节数在执行前进行有界枚举；估算与执行之间的文件变化、并发进程删除与复杂脚本分散操作无法准确计入。
17. **fail-closed 可能误拦。** 解析失败、运行时异常或某些规则命中会拒绝 / 询问正常操作。可在排障时使用 `monitor` 或紧急停机开关，但应谨慎恢复。
18. **审批能力依赖 Harness。** `ask` 需要宿主审批通道；没有可用审批 answerer 时按拒绝处理。这符合 fail-closed 目标，但会使某些“仅确认一下”的工具调用失败。
19. **对话内审批需要页面在线。** 如果无人点击审批按钮，请求会在默认 120 秒后按拒绝处理。关闭“对话内直接审批”可回退宿主审批界面。
20. **提示条不是权威审计。** 提示依赖客户端轮询，页面关闭或休眠时可能错过；权威记录应以 `vigil_audit` 读取的哈希链日志为准。
21. **对话审计 UI 依赖认证 Fetch 通道。** 没有对应宿主能力时，抽屉可能显示暂时无法读取；这不意味着运行时拦截同时失效。
22. **截断操作不能简单隔离恢复。** `Clear-Content`、`Set-Content`、`Out-File` 与 `>` / `2>` 是内容截断 / 覆盖，不等价于删除文件；此类操作按破坏性规则处理，但不移入隔离区。
23. **隔离区只处理明确且符合条件的目标。** 通配符、变量、管道、解析失败和 critical 根不会被擅自移动。跨卷目录复制最多 5000 个文件 / 512 MiB，超过限制会拒绝复制。
24. **永久清空不可恢复。** `vigil_quarantine action=purge` 与清空隔离区操作会永久删除对应条目；需要显式确认 / 二次点击。

## 4. 状态、日志与配置边界

25. **审计日志是尽力而为。** 日志写入失败会留下警告，但不反向改变已计算的 allow / ask / deny。停机开关期间主要记录 `pre-execute-bypass`，不会继续记录每次被绕过的细节判定。
26. **审计锚定并非远程不可篡改存储。** HMAC 锚点只能证明链头与持有密钥的一方所见记录一致。若攻击者同时拥有密钥与锚点文件，仍可重算；旧链与旧锚点一并回放，在没有外部独立副本时也可能难以识别。将锚点文件放在日志目录之外并由外部系统保管，可增强回滚检测。
27. **规则包锁不能防止同权限攻击者。** 外部规则包可 pin 文件哈希；内容变化、缺失或未登记时会拒绝加载。但同权限攻击者仍可能重写规则锁。锁的目标是发现意外漂移，不是防止有权限的恶意修改。
28. **设置页只暴露常用字段。** 保护根列表、白名单主机、Sage 签名公钥、外部规则目录与部分停机开关路径等高级字段可通过 YAML `config` 配置。设置页保存时只合并自己管理的字段，不应删除高级字段。
29. **安装后审计依赖 profile 布局与触发机制。** watcher 当前观察 `<DSH_HOME>/profiles/*/package.json` 与对应 `node_modules`；不符合该目录结构的自定义 profile 可能不被发现。插件管理事件可触发即时扫描，60 秒轮询作为兜底。
30. **本地 `link:` 安装存在源目录风险。** 在 Windows / DSH Desktop 某次实测中，卸载 / 更新清理触及 junction 源目录并造成部分 `.git` 元数据丢失。该记录不是所有 link 安装都会损坏的证明；但应使用一次性副本，日常安装优先固定 GitHub 提交。
31. **运行时依赖缺失会降级。** 缺少 `schemastery` 时设置页不可用但 Host 插件仍可运行；缺少 `acorn` 时 AST 别名分析跳过，其他文本扫描仍继续。
32. **Sage 检查范围有限。** Sage 当前只评估支持的执行 / 网络类工具（如 Bash、WebFetch、Read、Delete）；不会把 write / edit 正文送入引擎。单次异常通常降级到内置规则，除非 `sage.required` 开启。
33. **网络规则更新等于信任更新源。** 默认规则 manifest 指向本仓库 GitHub raw；jsDelivr 镜像可能存在约 12 小时缓存延迟。完全离线时将 `rules.source` 设为空字符串。外部 YAML 规则只包含数据，不执行代码。

---

> **部署建议：** 使用最小权限运行 Agent、备份关键数据、固定可信安装来源、先在 `monitor` 模式观察误报，再决定是否启用 `enforce` 与更严格的规则策略。

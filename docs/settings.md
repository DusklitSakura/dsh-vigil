# 设置页与对话内交互

> 设置入口：DeepSeek Harness → **Settings（设置）→ 守夜人**。设置页负责常用策略、运行状态与审批交互；独立的「插件审计」页签负责安装后的插件审计结果。

## 1. 设置页概览

### 自动保存与热更新

- 所有修改自动保存，不需要单独的保存按钮。
- 页面在最后一次修改后约 350 ms 空闲时写入；文本 / 数字输入不会逐字符独立落盘。
- 页面右上显示保存中、最近保存时间或失败原因。
- 并发写入会串行化；遇到修订冲突时会重新读取并重试一次。
- 写入的是 Harness volatile Config。大多数策略会在原地重建运行时并即时生效，不需要重新加载整个 bundle。
- Sage 模块路径 / 规则目录、审计日志目录等需要重新初始化子系统的字段，可能要到插件下次重载才完全生效；页面会对这类字段作提示。

### 分组与展开方式

设置页包含：

| 分组 | 主要内容 |
| --- | --- |
| 总览 | enforce / monitor 拦截开关、语言、快捷预设。 |
| 删除防护 | 保护根策略、递归 / 通配符 / 未知目标决策、阈值与项目根。 |
| 运行时哨兵 | 凭证、外发、动态代码、编码命令、配置篡改、持久化、插件安装、系统破坏与数据破坏。 |
| 隔离区 | 启用状态、保留时间、清理过期与清空。 |
| 自完整性 | 文件基线、金丝雀、周期检查与签名设置。 |
| 审计日志 | 日志状态、参数摘要隐私、轮转与锚定。 |
| 静态审计 | AST 开关与 finding 等级。 |
| 规则包与更新 | 外部规则目录、HTTPS 更新源、自动更新。 |
| Sage | 引擎启用、自动升级、灵敏度、超时与网络检查。 |
| 其他 | 自保护、管理工具与紧急停机开关。 |

页面默认只展开「总览」，展开 / 折叠状态会记忆。组级启用开关与折叠按钮位于标题行；关闭组开关后，其内部选项置灰。`monitor` 模式只记录 `wouldBe`，不会执行拦截，因此删除防护、运行时哨兵与隔离区相关操作会置灰或显示说明。

### 快捷预设

顶部提供 **宽松 / 标准 / 严格** 三档快捷预设。选择后会填充表单并自动保存；它不是 Host 内置策略引擎，而是 Client 表单侧的一组预设值。选择后仍可逐项调整。

### 状态监控板

标题下方的只读状态板显示：运行模式、停机开关、最近决策计数、隔离区用量、审计记录数、Sage 状态、规则包来源与完整性状态。数据来自只读 feed，可手动刷新。

停机开关启用时，守夜人设置页会显示停机提示卡，包括 DISABLED 文件路径、环境变量与恢复方法；普通配置表单不会继续显示为可操作状态。对话输入框上方的状态条也会显示“已停机”。需要查看全部子系统时使用 `vigil_doctor`。

## 2. 规则包更新

远程规则更新使用 HTTPS JSON 清单，例如：

```json
{
  "version": "2026.11.21",
  "files": {
    "sentinel.yaml": "https://example.invalid/rules/sentinel.yaml",
    "audit.yaml": "https://example.invalid/rules/audit.yaml"
  }
}
```

- 默认 `rules.source` 指向本仓库 GitHub raw 的 `rules/manifest.json`，请求直接读取，不经 jsDelivr 缓存。
- 「规则包与更新」分组提供更新源预设：GitHub、jsDelivr CDN、关闭远程检测或自定义 HTTPS 清单。
- jsDelivr 使用 CDN 缓存，分支内容可能延迟约 12 小时才可见。
- 将 `rules.source` 设为空字符串可关闭远程检测；插件仍可使用随包规则与本地外部 YAML。
- `rules.autoUpdate` 默认关闭；开启后按 `rules.updateIntervalMs` 检查，默认间隔 6 小时。
- `vigil_rules action=check` 检查版本；`action=update` 立即安装可用更新；`action=status` 查看本地规则来源；`action=verify` 检查规则锁；`action=pin` 固定当前哈希。
- 更新流程只接受 HTTPS；下载后逐文件校验 YAML，再原子写入 `<DSH_HOME>/vigil/rules`，刷新规则锁与版本文件。单文件大小及文件数量都有上限。
- 任一步骤失败都会保留上一份可用规则并显示 warning。YAML 是规则数据，不会执行其中的代码。

使用远程规则源意味着信任该 URL 的维护者。团队自建规则时应使用自己控制的 HTTPS 地址，并审阅变更。

## 3. 对话内审计提示

输入框上方的守夜人 dock（`conversation.input.dock`）显示：

- 最近拦截与询问的摘要，例如“拦截 2 · 询问 1”；
- 最近一条拦截 / 询问的时间、工具与原因；
- 「查看审计」入口；
- 仅当本会话存在“允许本会话”记忆时，才显示「取消始终允许」入口。

点击「查看审计」打开独立对话框，不会将对话内容撑开。默认只展示本会话的拦截 / 询问，可切换为显示全部。记录包含时间、工具、决策、原因、规则 ID 与 Sage 署名。插件安装审计不在这里展示，而是在插件页面的「插件审计」页签中查看。

Feed 默认保留最近 300 条决策，再按 session 投影，避免其它会话或子代理的调用把当前会话的拦截挤出列表。页面提示只是 feed 的展示，不替代哈希链日志。

### 对话内提示文案

- 可分别控制拦截提示总开关与是否显示 ask。
- `monitor` 模式下文案会说明“监控到一次本应被拦截的操作”，避免让用户误以为调用已经被阻止。
- Sage 命中会显示规则 ID 与来源署名，例如 `Sage 规则 CLT-…（@gendigital/sage-core, Apache-2.0）`。

## 4. 对话内审批

当最终决策为 `ask` 且启用「对话内直接审批」时，调用会等待页面回答，并在 root 级 `shell.overlay` 显示审批 modal。

### 用户操作

- **允许一次：** 只放行当前调用。
- **允许（本会话）：** 先显示二次确认，再记住当前会话中对应工具与规则组合的允许决定。
- **拒绝：** 拒绝本次调用。

关闭按钮、遮罩点击或 Escape 只会暂时收起 modal，不会自动批准调用；请求仍在等待并继续倒计时。默认等待上限为 120 秒，可由 `notify.approvalTimeoutMs` 修改；超时按拒绝处理并写审计。工具调用取消时，等待中的审批会撤销。

关闭「对话内直接审批」后，`ask` 回退到 Harness 原生审批界面。如果当前会话没有可用审批通道，按 fail-closed 规则拒绝。

### 页面未聚焦时的提醒

待审批请求出现且页面 / 窗口未聚焦时，可分别启用：

- Web Audio 提示音；
- Windows Notification API 通知（首次使用可能请求系统通知权限）；
- 吸引 DSH 窗口注意：桌面 Host 可带到前台并临时置顶，其他 Host 按能力降级为任务栏闪烁。

三项提醒相互独立。系统拒绝通知权限只影响通知，不会自动关闭其他提醒。请求处理完毕或窗口重新聚焦后，临时置顶 / 闪烁应停止。

若请求来自其他会话或子代理，弹窗会显示来源会话信息。

## 5. 安装审计页面

插件页面的独立 `plugins.tab` 页签名为「插件审计」，不依赖当前对话会话。

- 每个插件显示名称、风险等级、扫描原因、扫描时间与发现摘要。
- 「详情」展开规则标题、文件 / 行号、证据与风险说明。
- 支持单插件重新扫描与全部重新扫描。
- 安装 / 更新自动扫描会在完成后显示近全屏提示浮层；手动重扫只记录观察事件，不冒充审批询问。
- 本地路径安装由安装门禁执行前扫描；GitHub / registry / tarball 安装在完成后扫描。
- 如果扫描存在文件跳过、截断或覆盖不足，安装门禁会询问，不会把“未扫描到”说成“无高危”。

## 6. 审计与隔离区生命周期

### 审计日志清理与对话生命周期

- 设置页提供清理全部会话审计记录的确认操作。
- 对话「查看审计」工具栏提供清空当前会话记录的确认操作。
- 清理后会重写存活记录哈希链，并留下 `audit-clear` 事件；`vigil_audit action=verify` 应继续可用。
- 归档会话时，其记录移入 `<DSH_HOME>/vigil/log/archive/` 并产生 `audit-archive`；取消归档时恢复并产生 `audit-restore`；删除会话时同步删除并产生 `audit-delete`。

这些行为由 Harness 的 `workspace/session-archived`、`workspace/session-unarchiving` 与 `api-session/removed` 事件触发。日志清理属于破坏性维护操作，不要在插件运行时从文件管理器手工删除活跃日志 chunk。

### 隔离区

隔离区分组可查看条目数、估算体积与保留时间，并提供“清理过期”与需要二次确认的“清空隔离区”。清空是永久删除；只需释放过期数据时，应使用清理过期。

## 7. 已认证 Fetch 路由

Client 与 Host 的数据交互通过认证的 `connection.fetch` 通道。当前主要接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/dsh-vigil/audit` | 读取脱敏决策摘要、审批状态、安装审计、隔离区快照与状态。 |
| `POST` | `/api/dsh-vigil/approval` | 回答待处理审批请求。 |
| `POST` | `/api/dsh-vigil/audit-clear` | 清理全部日志或指定会话日志。 |
| `POST` | `/api/dsh-vigil/sage-action` | 卸载自动下载的 Sage 引擎与规则。 |
| `POST` | `/api/dsh-vigil/quarantine` | 清理过期条目或确认清空隔离区。 |
| `POST` | `/api/dsh-vigil/install-scan` | 对指定插件或全部已安装插件重扫。 |

未认证请求会由 Harness 认证通道拒绝。新增接口不得改为裸 Web Server 路由。

## 8. 高级 YAML 配置

设置页只管理常用字段。团队或维护者仍可在 `cordis.patch.yml` 对 bundle 行提供未在 UI 暴露的字段：

```yaml
- insert:
    - id: dsh-vigil
      name: dsh-vigil
      config:
        mode: enforce
        locale: zh
        sentinel:
          allowedHosts: ['registry.npmjs.org']
        deleteGuard:
          extraHighRoots: ['D:/Dev/important-repo']
```

设置页保存会合并它管理的字段，不应删除 YAML 中的其他配置。非法值会回退到默认值，并可从 `vigil_status` 的 `configWarnings` 查看警告。
